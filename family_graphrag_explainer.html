What Does family_graphrag.py Do?

Standard RAG (Retrieval-Augmented Generation) chops documents into plain text chunks and relies purely on semantic similarity. While great for simple lookup, it fails on complex questions like: "Does our health insurance cover Dad's cataract operation performed at Apollo last month?" because the hospital discharge memo, the policy schedule, and the kinship relation ("Dad" = Saibabu) live in separate documents.

The Dual-Memory Architecture

family_graphrag.py bridges this gap by creating two complementary stores from your extracted text:

1. Vector Store (ChromaDB)

Stores chunk embeddings created with bge-small-en-v1.5. Finds the closest raw passages matching your query with page numbers and timestamps.

2. Graph Database (Neo4j)

Connects Person, Organization, Asset, and Category nodes with typed relationships (SUBJECT_OF, ISSUED_BY, INSURES, PARENT_OF) allowing multi-hop reasoning.

The Two-Pass LLM Ingestion Pipeline (build)

Processed via process_doc() in lines 1137-1176. Each document undergoes two dedicated extraction passes with local LLM prompts:

PASS 1

🗂️ Document Card Extraction

1 LLM Call Per Document (extract_card)

Inspects the header and opening/closing pages to extract document-level metadata without getting bogged down in body text:

  • Document Category: 30+ standardized types (e.g., health_insurance, education_certificate).
  • Subject / Holder: Family members with roles (student, patient, policyholder).
  • Issuer: Organization (e.g., Star Health, Osmania University).
  • Dates: Issue date, expiry date, renewal deadlines, due dates.
  • Financials: Sum insured, fees paid, invoice total, currency.
Powers the expiring and profile commands directly!
PASS 2

🧬 Chunk Entity & Relation Extraction

1 LLM Call Per Chunk (extract, multi-threaded)

Segments long documents into page-aligned chunks (~1,500 chars) and performs schema-constrained extraction:

  • Entity Recognition: Extracts Person, Asset, Organization, MedicalCondition, EducationalDegree.
  • Typed Relationships: PARENT_OF, DIAGNOSED_WITH, PRESCRIBED, PURCHASED, INSURES.
  • Grounding & Evidence: Stores the verbatim quote backing the relationship directly in rel.evidence.
  • Parallel Workers: Uses Python ThreadPoolExecutor to run multiple chunk extractions in parallel.

⚡ Smart Incremental State & Resume (state.jsonl)

The script computes a SHA-1 hash of the file text. If a file is already indexed in data/graph/chroma/state.jsonl and its content hash has not changed, it is skipped instantly. If you add 5 new PDFs to an archive of 200 documents, build only calls the LLM on those 5 new files!

Neo4j Graph Database Schema

The ontology strictly defines node labels, constraints, and relational edges to guarantee fast Cypher traversals:

Core Graph Nodes

:Document

Represents a file. Stores id, title, category, expiry_date, amount, doc_number.

:Chunk

A page or text segment. Stores chunk id, text, locs (e.g., page 3-4).

:Entity

Resolved person, organization, asset, or condition. Stores normalized key, name, type.

:Folder & :Category

Preserves directory hierarchy (CONTAINS) and document taxonomy (IN_CATEGORY).

Graph Relationships (Edges)

Structure:
(:Folder)-[:CONTAINS]->(:Document)
(:Document)-[:HAS_CHUNK]->(:Chunk)
(:Document)-[:IN_CATEGORY]->(:Category)
People & Issuers:
(:Entity {type:'Person'})-[:SUBJECT_OF {role}]->(:Document)
(:Document)-[:ISSUED_BY]->(:Entity {type:'Organization'})
Chunk Mentions & Facts:
(:Entity)-[:MENTIONED_IN]->(:Chunk)
(:Entity)-[:REL {type, evidence, date, amount}]->(:Entity)
Family Tree (from family.json):
(:Entity)-[:REL {type:'PARENT_OF'|'SPOUSE_OF'}]->(:Entity)

Family Alias Resolution (config/family.json)

Functions normalize_name() and resolve_family() map informal speech ("Mom", "Dad", "my", "Botte Saketh") to the exact canonical person key (saketh, saibabu). When you query about "my marks", it automatically queries Saketh!

Hybrid Retrieval: How ask Works

The ask command combines vector similarity search with multi-hop Cypher graph traversal in 4 synchronized steps:

Step 1 · Identity & Vector Retrieval (ChromaDB) Lines 1283-1296

Resolves pronouns ("my" → Saketh). Embeds the query using bge-small-en-v1.5 and retrieves the top K seed chunks from ChromaDB.

Step 2 · Graph Fact Expansion (Neo4j) FACTS_CYPHER (Line 1234)

Takes the seed chunks, finds all entities mentioned in them (:MENTIONED_IN), and collects all graph relationship edges connected to those entities ((:Entity)-[:REL]-(:Entity)).

Step 3 · Multi-Hop Extra Chunk Discovery EXTRA_CHUNKS_CYPHER (Line 1249)

Finds other document chunks in the vault that mention these same entities or their 1-hop graph neighbors. This allows the LLM to connect separate documents that vector search alone would have missed!

Step 4 · Cited Synthesis with Local LLM ANSWER_PROMPT (Line 300)

Packs the graph facts, document cards, and ranked sources into a strict prompt. The LLM answers the question, citing facts with [1], [2] matching the source transcripts.

CLI Subcommands Reference

Everything family_graphrag.py can do from the command line:

build Index Vault

Extracts cards and entities, updates ChromaDB vectors and Neo4j graph.

python -m src.family_graphrag build --src "data/extracted/text" --workers 4
ask Question Answering

Runs vector search + graph expansion to answer complex family questions.

python -m src.family_graphrag ask "What are my marks in intermediate?"
expiring Deadlines & Expirations

Queries Neo4j for upcoming warranties, renewals, and deadlines in the next N days.

python -m src.family_graphrag expiring --days 90
profile Member Dossier

Compiles all IDs, educational certificates, policies, and relations for one person.

python -m src.family_graphrag profile "Saketh"
estimate Token Cost Preview

Sizes the vault before spending inference time: computes doc counts, chunk counts, and estimated LLM tokens.

python -m src.family_graphrag estimate --src "data/extracted/text"

Privacy Protection & PII Masking

Because family archives store sensitive personal information, security is baked into the code at two levels:

🛡️ The Local-Only Firewall

In function llm_client() (line 494): 

if not LLM_IS_LOCAL and not ALLOW_REMOTE_LLM:
    sys.exit("LLM_BASE_URL is not local!
Personal documents would leave your control.")

The script parses the LLM host IP/hostname and strictly blocks any remote internet endpoints unless you explicitly set ALLOW_REMOTE_LLM=1.
